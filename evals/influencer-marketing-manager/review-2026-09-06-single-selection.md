# 客户提报：单一名单生成与输出核对

**结论：本轮不采用 Skill 接入。** 五人比较有所改善，但最终缺口回归仍将不合格的 C 放进推荐表。已将 `skills/` 与 `experts/` 恢复到 `89605f5`；本次仅保留本地工具原型、测试、执行观测和复盘，不宣称业务流程已改善到可发布。

## 本轮目标与改动

解决[上一轮](review-2026-09-06-client-batch.md)的两类具体矛盾：最终名单与表格行不一致；报价比较与已知金额不一致。继续遵守用户的五人比较、判断与证据分开、共同动作不逐人重复的要求。五人是本项目目标，不是通用默认值。

试验增加了一个 Python 标准库只读工具：模型先依据项目材料评估资格、真人回复和合作条件，再提交稳定 ID、入选名单和展示字段。工具从同一份入选名单生成表格，检查数量、去重及分币种的已知报价最小值。它不验证模型声明是否忠于原始资料，不代替业务选人，也不批准合作。回退后保留在 `evals/influencer-marketing-manager/tools/render_shortlist.py`，不随 Skill 分发。

曾在主 Skill 增加客户提报入口，细节放在 `references/client-shortlist.md`，并调整 playbook 的展示字段；这些接入改动均已回退。评测报告保留工具输出和表格传递观测，不增加业务分数、模型 judge 或新平台。

## 固定口径与有界修正

- 请求模型固定为 `gpt-6-astra` / medium；结果缓存关闭，串行、只读、隔离运行，无营销系统访问。
- 23 个 canonical case、合成输入、outcome grader 和用户业务评审标准均未修改。Promptfoo 绿色行仅证明相应自动证据检查通过，客户提报仍由人工评审。
- 首次 case 22 在读取资料阶段触及五分钟上限，未产生回答。只将单行上限改为十分钟，全套仍限二十分钟；该次超时保留，不算业务通过或失败。
- 首版复测暴露了两项执行问题：一份回答只找到脚本而未运行；另一份运行后又翻译了表格单元格。后者没有改错名单或报价，但不能算原样传递。
- 最后只补了生成前准备客户语言、只读 shell 使用管道的说明。实际 trace 中 heredoc 因临时文件权限失败，改用 `printf` 管道后成功；未扩大沙箱权限。同时修复本地测试发现的 URL 中竖线／反斜线可破坏 Markdown 表格的问题。

## 最后回归与回退决定

| Case / 最终候选 | Agent 预评 | 主要依据 |
| --- | --- | --- |
| 23 / 缺口 | 需要关键修改 | 错称两位可进入本轮、缺口三位，将不满足长视频门槛的 C 作为备选推荐。工具输入将 C 标为 `eligible=true`，因此机械检查通过；最终表格也未原样复用。 |
| 9 / 内部粗筛 | 可用作粗筛优先级 | 优先精审 B/C，保留 B 的匹配价值与联系缺口，未把客户提报的真人回复要求或生成工具套入内部研究；未声称完成浏览器精审。 |
| 12 / 缺源翻译 | 范围检查通过 | 只索要缺失的原邮件，没有加载 Manager 或虚构翻译；不是翻译质量评测。 |

case 23 的关键矛盾可直接复核：开头写“按符合项目要求 + 有真人回复筛选后，仅 2 位”，C 行却写“不满足当前长视频门槛”。脚本收到 A/C 两个合格声明，返回两人、缺口三人和 C / USD 600 的已知最低报价。这不是算术错误或缺少材料，而是**已读到的资格事实没有约束最终推荐，错误声明又被传入工具**。

因此停止本轮调优，回退 Skill 接入。保留工具原型的机械能力，但不把它当作资格审核器。下一轮应先隔离测试“原始内容事实 → 是否具备当前提报资格”，确认判断能够约束名单，再考虑接回生成工具；不需要扩大测试平台、放宽资格或继续堆提醒。本轮没有证据足以将失败归因于某一句新提示词。

共 9 次执行、8 份回答、1 次运行超时；8 份回答的自动证据／范围检查通过，但包含上述业务失败。未做全量自然触发测试、真实发现或邀约，用户尚未认可本轮模型回答。

回退后本地验证通过：23 个 case 定义、adapter/grader 自测、32 个单元测试、Promptfoo 配置与快照检查、官方 Skill 校验、Expert 同步、原文一致性、Markdown 链接和空白检查。重新准备的基线与当前 Skill 指纹相同；原 case、输入、grader 和业务评审标准无差异。这些是本次验证资产的提交依据，不是被回退候选的业务通过证明。
