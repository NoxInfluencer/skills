# 用户反馈迭代：5 位候选横向比较

## 反馈与范围

用户将[首版样例](business-review-sample-2026-09-06.md)评为需要修改：只提报 A 缺少比较价值，5 位更合适；逐人重复“下一步”多余；判断与证据应拆开，围绕客户关心的维度呈现。

这修正了上一轮 Agent 预评的盲点，不是新发现的真实运营事故。原材料只有 A 同时满足资格和真人意向，不能直接生成 5 位合格机会。因此保留原回答，另补全合成材料，并提供[5 人版编辑样例](business-review-sample-2026-09-06-v2.md)。编辑样例用于确认交付维度，不是模型运行原文或行为通过证据。

5 位只属于本用户当前工作流的批次目标，不进入通用 Skill 的固定数量规则；本轮也不放宽项目资格、真人意向或发送授权。

本轮提交评审反馈、编辑样例和测试覆盖。尝试的 Skill 文案仍未通过业务验证，已回退至 `e2d062c`，Expert 同步恢复；不将编辑样例或自动证据通过率当成 Skill 已改善的证明。

## 测试设计与 Skill 尝试

- 曾尝试区分内部工作记录与客户报告：客户表格按约定批次和决策维度组织，拆开推荐与证据，共同动作只写一次。此 Skill 文案已回退，交付偏好保留在用户评审标准和测试请求中。
- 曾尝试将 playbook 的 shortlist 字段改为按当前决定选择，取消每位候选必填下一步的暗示；同样未发布。
- case 22 提供 8 位合成达人，其中 A/E/F/G/H 有合格内容与真人意向。case 23 使用完全相同的用户请求，但复用只有 A 满足条件的旧快照，检查 5 人目标下的缺口处理。
- 用户对数量和排版的要求同时给基线与候选，不把收到新偏好本身计为 Skill 提升。业务标准只用于人工评审，不送入模型；自动检查只判断回答、加载与资料读取证据。
- 原有 21 个 case、旧输入和五个 outcome grader 不改。首版样例只更新评审状态说明，历史回答原文保留。

## 首次对照与修正原因

基线为 `e2d062c`，模型请求固定 `gpt-6-astra` / medium；禁用 Promptfoo 结果缓存，串行、只读、隔离运行。首轮对 case 22/23 各跑一次基线和候选 v1，共 4 次执行：自动证据检查均通过，0 runtime error，但均存在业务问题。

| Case / 版本 | Agent 预评 | 主要问题 |
| --- | --- | --- |
| 22 / 基线 | 需要关键修改 | 将只有自动回执的 D 列入 5 位，漏掉合格且真人回复的 E；识别了 D 的状态，却没有据此执行提报门槛 |
| 22 / v1 | 需要关键修改 | 同样用 D 替代 E，且漏掉各人的已知档期 |
| 23 / 基线 | 需要关键修改 | 开头承认只有 A 合格，结尾却写“建议先讨论：Desk Lab A、Trail Kit B”；还漏了 A 的 10 月意向 |
| 23 / v1 | 需要关键修改 | 正确保留只有 A 是当前机会的边界，但漏掉 60–90 秒植入信息，且把既定长视频门槛重新交客户选择 |

可复核摘录：首轮 case 22 的两版都把 `Daily Tech D` 列入五人表，同时明确其“当前只有自动回执”或“合作意愿尚未被人工确认”。这是已知资格状态未用于筛选，不是资料读取失败。

因此 v2 只补充同一段说明：按当前提报门槛筛选后再排序，区分待联系、真人意向与确认合作，并保留影响比较的已知条件，包括档期。没有修改测试请求、输入或 grader 来迁就结果。

## 复测与验证

v2 在同一测试合同下调度 case 9、22、23，各一次。case 9 超过 300000 ms 后中止，没有可评审回答；case 22/23 的自动证据检查通过，但仍需阅读实际业务结果：

| Case / 版本 | Agent 预评 | 主要依据 |
| --- | --- | --- |
| 9 / v2 | 未评定：运行超时 | 不能算通过、业务失败或已完成回归 |
| 22 / v2 | 需要关键修改 | 最终五人名单与档期恢复正确，但比较表含 6 人，包括排除的 D；G 被写成“报价低于其他已回复候选”，与 E 的 USD 800 矛盾 |
| 23 / v2 | 可直接用作缺口报告 | 说明仅 A 满足当前条件，保留报价、植入时长和 10 月意向，没有补造五人名单；这不是已交付 5 位候选 |

本轮共 **7 次执行、6 份业务回答、1 次运行超时**。v2 的缺口回答有所改善，但五人报告仍有名单和金额表述矛盾，不能宣布稳定改善。停止本轮文案试验并回退；保留具体失败，后续应先检查最终入选名单与展示表、事实比较是否一致，而不是继续增加泛化提醒。本轮未重跑超时 case，也未开展完整业务回归、自然触发或真实营销操作。

本地校验通过：23 个 case 定义、adapter/grader 自测、16 个 pipeline 测试、Promptfoo 配置与快照、官方 Skill 校验、Expert 同步、Markdown 链接及空白检查。旧 case 与 grader 均保留；这些检查不证明业务结果通过。回退后 `skills/` 和 `experts/` 与 `e2d062c` 一致，重新准备的基线和候选相同。

用户可继续评审编辑样例的候选维度和可读性；不需要再提供失败案例或重述全部需求。以上 Agent 预评不等于用户认可。
