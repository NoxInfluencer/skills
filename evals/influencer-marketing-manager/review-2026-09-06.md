## What the original answers and traces show

**Cold start:** the candidates generally avoided unsupported creator counts, but that did not make the whole task better. All three C answers omitted the 3–5 representative-piece default. One substituted "roughly three to six months" for the baseline's inspection window; another explicitly left the window unset. The single automated pass therefore does not establish complete task success.

**Reference use:** all three fresh baseline cold-start runs read `experience-baseline.md` and `playbook.md`. B's one fully covered cold-start answer also read both; C's three cold-start runs read only `SKILL.md`. The main file itself still contained the sampling guidance. This is evidence of inconsistent instruction/reference use, not proof that reference loading alone will fix it.

**Outreach:** B's stronger answers separated fit, contact-pending and send authority, with concrete recipient/message checks. Its failing answer defined `contact-ready` as both a route and authorization and omitted concrete pre-send verification. C still sometimes mixed contact readiness with workflow states such as draft, sent and replied. The 2/3 result does not establish a stable fix.

**Grader limits:** "Temporary Defaults" can convey provisional status without matching that smoke check. C's `细审` wording was not recognized by the coarse/fine matcher, while one incomplete cold-start answer still passed. Keep these recorded scores unchanged; classify wording issues separately from missing evidence or contradictory decisions. This review did not relax or expand the graders.

The approved-capacity probe and unaffected-case model checks were not run after C failed the release decision. No unsupported numeric rule, fixed output template, new judge, or dependency was added to force a pass.
