# Campaign Agent Automation MCP Adapter

Product operations use `list_products`, `get_product`, `create_product` and `update_product`. Creation accepts custom-product name, brand, description, reference link, thumbnail URL and other schema-supported metadata; a name-only custom product does not require an external ID. Keep `product_collect_id` opaque.

Use `campaign2_products_add` with string `campaign_id`, exactly one of `product_collect_id` or inline `product`, explicit `mode: "draft" | "apply"`, and a stable `idempotency_key`. Inline `product` uses `name`, `brand`, `description`, `link`, `thumbnail_url`, decimal-string `price_min/price_max`, `currency`, and optional `product_kind/service_type` per the schema. This has the same business meaning as the CLI addition command. `apply` affects only this product; it does not apply the rest of the plan draft. Read `changed`, `mode`, `product` and `settings` from the result. Select these tools independently according to `campaign-products.md`.

Use the connected provider's `campaign2_*` tools and live input schemas. Pass JSON arguments directly; there is no CLI body-file wrapper. If a required tool is absent, report unavailable instead of inventing a result or using generic email tools.

Read `campaign2_context` for the current Campaign and applied settings. Use `campaign2_plan_list/init/create/get/settings_save/settings_apply/status/members/copy/overview` as individual tool names with the `campaign2_` prefix and underscores. Keep Campaign IDs as strings. Draft saving, applying settings and sending are separate operations.

Use `creator_search` for interactive evidence. Use `campaign2_discovery_search` only with an authoritative returned `task_id`, never an invented task ID. Use `campaign2_search_condition_get/save` when maintaining the current search condition. Keep search conditions, result summaries and evidence in the Campaign conversation, and save selection reasons with business list writes. Do not call `campaign2_discovery_snapshot_save` or persist separate discovery-result snapshots. Never rerun a search only to reproduce a historical page.

Read candidates and exclusions with `campaign2_candidates_list` and `campaign2_not_interested_list`. Preserve `data.items`, platform counts, page totals, `creator_id`, `profile_status` and `plan_note`. Use `campaign2_candidates_add/remove`, `campaign2_not_interested_mark/restore` and `campaign2_invitation_pending_add` for authorized curation. The server owns permissions, deduplication and protected states. Use `campaign2_auto_discovery_settings_get/settings_save/settings_delete/switch` for existing automation settings.

Read the shared cooperation and invitation references before using `campaign2_cooperations_*` and `campaign2_invitations_*`. Preserve returned raw channel identity and record version for cooperation edits; do not rename encrypted creator tokens into channel IDs. Invitation targets use returned `creator_id`; only schema-supported X targets without tokens use verified raw `channel_id` with platform 3.

Use `campaign2_invitations_preflight` for authoritative selected-contact checks before a start preview. The additional read/maintenance tools are `campaign2_invitations_detail/readiness/regions/settings_reset`, `campaign2_auto_advance_settings_get/settings_apply`, `campaign2_automations_get/switch`, `campaign2_plan_metrics`, `campaign2_notes_save`, and `campaign2_cooperations_labels_list/label_create/label_update/label_delete/label_assign`; these are individual tool names under the same prefix. Copy `data.items[].invitation_sender` from sender options into `settings.sender`, preserving `type` and all selected `authInfoIds`, including Nox type 3.

Candidate/exclusion lists support the declared server-side `filters` and raw `channel_id` plus platform for X. Invitation filters use `min_sub`, `max_sub` and `regions`; preserve them for all-matching cancellation. Automatic discovery saves use `settings:{enabled,config}`. Record-save has `mode:"full"` for complete details and `mode:"inline"` for partial Campaign details, with required name/version/status preserved. Explicit relation IDs are required for restoring unsuitable creators; all-selection is not supported.

For an explicit request to add creators to the current Campaign negotiation list, use `campaign2_cooperations_add` with string `campaign_id`, verified `creator_url`, and a stable per-creator `idempotency_key`. Use one call per selected creator with bounded sequential execution and list readback. This reuses manual membership addition; it is separate from formal `campaign2_cooperations_record_save`, invitation-pending imports and account-level CRM. If the tool is missing or rejects the request, report that limitation without changing the destination.

Every mutation requires a stable `idempotency_key` of 8–128 characters. For `campaign2_invitations_send`, submit action, explicit targets, Campaign ID, attempt key and `phase:"preview"`. Show `data.review`, respect blockers and require `data.can_execute:true`. Wait for a separate affirmative user reply. Execute the same tool with unchanged business arguments and key, `phase:"execute"`, returned `confirmation_token`, and `confirmed:true`. The token is bound to subject, client, Campaign, action and reviewed arguments; it expires within five minutes. Revalidation or expiry requires a new review and confirmation.

On timeout or unknown outcome, call `campaign2_invitations_send_result` using `execution_key` equal to the original attempt key. Accepted is not sent or delivered. Never resend with a new key to bypass an uncertain result. `campaign2_plan_delete` uses the same phased review protocol. External clients do not emit SaaS CLI workspace navigation receipts.

## Bulk cancellation

For bulk cancellation, call `campaign2_invitations_state` once with `campaign_id`, `action: "cancel"`, 1–1000 distinct `targets`, and `idempotency_key`. Set `status_group: "queued"` for the queued list; omission or `waiting` keeps strict waiting cancellation. Alternatively use `all_matching: true`, `expected_count`, the same status group and exact supported filters for an authorized all-matching selection. Report `data.cancelledCount` and `data.skippedCount` separately, including a successful response with zero cancellations. Follow the bulk cancellation section in `{baseDir}/references/campaign-invitation-management.md`. Never loop single-creator `target` calls. If the connected tool schema lacks batch arguments, report the deployment gap rather than claiming success or falling back to individual cancellation.
