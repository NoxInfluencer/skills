# NoxInfluencer Product Workflows

## Plugin execution rules

This is the plugin entrypoint. Read these rules before [upstream.md](upstream.md), the complete upstream business guidance, then load only the references needed for the task. Apply these rules to upstream.md and every copied reference; do not treat the upstream frontmatter, installation metadata, or execution instructions as an active CLI Skill.

- Use upstream guidance for product knowledge, business sequencing, data meaning, evidence limits, costs, write side effects, and the user's business authority. Ignore its CLI/CLI Connector routing, commands, flags, shell examples, version requirements, installation, Device Flow/API-key login, local credentials, diagnostics, and CLI response-envelope assumptions.
- Before a NoxInfluencer business read or write, explicitly read [the MCP execution entrypoint](../mcp/SKILL.md) (`noxinfluencer-mcp`) and its required runtime references. If already loaded, reuse that contract without recursively reloading this entrypoint. The connected `noxinfluencer` MCP provider is the only NoxInfluencer business backend.
- Translate the intended business operation using the live Tool description and input/output schema. Never execute an upstream command or mechanically turn its command name, flags, field paths, pagination, dry-run default, or automatic idempotency behavior into a Tool contract. An upstream capability is not evidence that its MCP Tool exists.
- If a Tool or required field is unavailable, report the affected step and continue independent supported work. Do not install or use the NoxInfluencer CLI, call an API directly, or switch to SaaS browser automation to fill the gap.
- OAuth, connection recovery, account identity, retries, page opening, browser choice, and signed-in Browser Handoff follow the MCP runtime exclusively. Ignore upstream external-browser and embedded-browser prohibitions. Only the Host authorization helper explicitly permitted by the MCP contract may use a shell; it is not a CLI business backend.
- Retain approval scope, material commercial decisions, quota implications, recipient checks, and authoritative readback. Ignoring CLI execution does not remove a business constraint or authorize a send. Use MCP previews and confirmation requirements when exposed; do not assume CLI flags exist.

## Read the business guidance

Read [upstream.md](upstream.md) for the requested product workflow, then follow its relevant local references. `{baseDir}` means this directory. `references/cli-response-format.md` is deliberately excluded: skip that upstream reference and never recreate or fetch it. The original text, including CLI examples, is preserved as reference material under the execution rules above.

For goal selection, marketing strategy, negotiation, message drafting, or cross-stage SOPs, read [the Manager entrypoint](../influencer-marketing-manager/SKILL.md) when needed. Keep product evidence scoped to what was checked; the Manager owns the wider business judgment. Business guidance comes from the shared upstream files; MCP-specific runtime contracts govern actual execution.

`upstream.md` and copied resources are generated by `npm run skills-plugin` from the repository root. Maintain business guidance in the outer source Skill; maintain this plugin entrypoint separately.
